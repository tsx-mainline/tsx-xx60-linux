# chromium pulls in icu-data-full (31 MiB) as a hard dependency (its APKBUILD
# names the package "icu-data-full" itself, not the "icu-data" virtual that
# icu-data-en also provides), so `apk add` refuses to substitute icu-data-en:
# "conflicts: icu-data-full[icu-data]" / "satisfies: chromium[icu-data-full]"
# (verified with `apk add --simulate` against this Alpine release). Keep it.
#
# Pinned to the exact build src/chromium-es2/sigs.json has a signature for
# ("alpine-v3.24-armv7-chromium-152.0.7977.82-r0"): apk records this "="
# constraint in the rootfs's own /etc/apk/world, so `apk upgrade` on the
# panel can never silently move chromium past what the ES2 patch covers --
# it would refuse (no candidate satisfies the world constraint) rather than
# ship an unpatched, software-rendered browser. To move the pin: derive a
# new sigs.json entry for the target version first (src/chromium-es2/README.md,
# "Re-deriving for a new Chromium package"), then bump the version here and
# rebuild.
chromium=152.0.7977.82-r0
